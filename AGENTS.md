# Repository Agent Instructions

## Deployment model

- This application is deployed from the Git repository through the Vercel Git integration.
- Do not treat `dist/index.html` as a deployment input, source file, release artifact to commit, or file to upload manually.
- Do not edit anything under `dist/`. The directory is generated by `npm run build` and is intentionally ignored by Git.
- Make application changes in `src/`, `api/`, and the source `index.html` at the repository root.
- `npm run build` is a verification step. Vercel runs the build again from the committed source when it deploys.
- A push to the configured Production branch (`main`) creates a Production deployment. Other branches create Preview deployments.

## Hosted and standalone modes

- The hosted application consists of the Vite frontend plus the Vercel Function at `/api/config` and a connected private Vercel Blob store.
- HTML produced by the application's **Export HTML** action is an offline snapshot for users. It is not the hosted deployment artifact.
- Exported HTML must continue to disable Refresh, Save, and Force Save while retaining local editing, Import HTML, and Export HTML.

## Vercel Functions

- Keep Vercel Functions under the root `api/` directory.
- This repository uses native ESM. Relative imports in the Function and every local module reachable from it must use emitted `.js` specifiers, even when the source file is TypeScript. Example: `../src/configSchema.js`.
- Production and Preview Blob access should use the OIDC credentials and `BLOB_STORE_ID` injected by the Vercel Blob project connection. Do not force a long-lived `BLOB_READ_WRITE_TOKEN` in hosted code.
- `KPI_LIBRARY_SECRET` is server-only and must never use a `VITE_` prefix or be embedded in browser code.

## Verification

- Run `npm run build` after relevant changes.
- For hosted behavior, use `npx vercel dev`; `npm run preview` serves only the static build and does not provide `/api/config`.
- When a deployed Function works locally but returns `FUNCTION_INVOCATION_FAILED`, inspect Vercel Runtime Logs. Do not assume the generated `dist/index.html` is responsible.
- See `docs/VERCEL_DEPLOYMENT.md` for deployment, environment, and troubleshooting details.
